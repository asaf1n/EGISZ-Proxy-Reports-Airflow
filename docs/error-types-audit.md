# Типы ошибок: архитектура и проверка 15 сентября 2026 года

## Что подтверждено на рабочем контуре

Проверены PostgreSQL `dwh_egisz`, Metabase `https://bi.sdsys.ru` и Airflow
`https://airflow.sdsys.ru`. Реквизиты использованы из переменных окружения, значения
секретов не сохранялись. API Airflow доступен с авторизацией; оба DAG ЕГИСЗ включены,
состояния metadatabase и scheduler — `healthy`.

В DWH на момент первоначальной проверки было 545 013 документов. У 61 358 поле
`error_types` содержало несколько типов. Это снимок проверки, а не постоянные показатели.

На дашборде 34 «Интеграция с ЕГИСЗ» фильтр `error_type_filter` уже был привязан к
атомарному полю `rpt_error_breakdown.error_type` (Metabase field 639). Однако из пяти
карточек вкладки «Анализ ошибок» привязка была только у карточки 834
«Ошибки: тип × клиника». Карточки 828, 829, 830 и 832 игнорировали выбранный тип.
Поэтому проблему нельзя исправить одной заменой списка значений фильтра.

На рабочей вкладке пять карточек, в исходном JSON семь. Полный импорт JSON изменит
состав и расположение карточек. Для выкладки этих исправлений следует обновлять
запросы и привязки существующих карточек, сохраняя опубликованную раскладку.

## Причины

1. `build_errors_json` корректно извлекает отдельные `item` и `RegistryError`.
   Затем `error_classify` и `error_messages_row` сворачивали их в независимые строки.
   Принадлежность кода, текста и OID одному элементу не сохранялась в документном слое.
2. `rpt_error_breakdown` восстанавливала типы разделением строки по ` · `.
   Такой разделитель может встретиться и внутри сообщения. OID искались в общем тексте
   документа; два справочника одного класса превращались в «несколько справочников».
3. Правило по коду подменяло читаемый текст. Под кодом ошибки построения цепочки
   сертификатов фактически встречается сообщение «Срок действия сертификата организации
   истек или еще не наступил». Подмена наименованием кода меняла смысл причины.

## Изменённый контракт

`transactions.error_details` и `documents.error_details` хранят JSON-массив элементов:

| Поле элемента | Смысл |
| --- | --- |
| `code`, `message` | Исходная пара из ответа |
| `error_type` | Читаемая формулировка с нормализацией переменных реквизитов либо интерпретация технического сообщения |
| `classification_type` | Ключ правил классификации для категории и служебных признаков |
| `nsi_dictionary_oid` | OID из этого элемента ответа |

Преобразования выполняются в PostgreSQL. Airflow сохраняет прежнюю роль оркестратора.
JSON рассчитывается один раз на уникальный payload батча. Обновление документа
подчинено тому же условию актуальности callback, что `error_text` и `result_logid`.
Поле `error_types` остаётся сводной строкой для журнала; отчёты используют структурированные элементы.

`rpt_error_breakdown` остаётся материализованной витриной поверх постоянных фактов
`documents` и справочников. Уникальная пара — `dwh_id` и отображаемый `error_type`.
К подписи добавляется `OID <идентификатор> · <полное наименование>`.
Для отсутствующего в реестре OID наименование не выдумывается.

Фильтры всех карточек используют отдельное значение `rpt_error_breakdown.error_type`.
Несколько значений объединяются по «или». Подсчёт уникальных документов и `EXISTS`
не допускают умножения документа при нескольких ошибках. Фильтр изменяет числитель;
знаменатель доли сохраняет документный набор периода согласно смыслу карточки.

## Перенос архива и выкладка

1. Приостановить на время изменения схемы DAG, работающие с DWH, и дождаться завершения
   текущих задач. Сохранить определения схемы и JSON обновляемых карточек.
2. Применить `db/dwh_init.sql` из проверенной рабочей копии или заново собранного пакета.
3. Запустить `scripts/backfill_error_details.sql`. Он восстанавливает элементы только
   выбранного ответа документа из соответствующих `transactions` и `exchangelog_raw`.
   Курсоры ELT не меняются. Пакеты фиксируются отдельно; повторный запуск продолжает
   обработку оставшихся `NULL` и не переписывает уже перенесённые документы.
4. Проверить выведенное число `documents_without_error_details`. Ненулевой остаток
   означает отсутствие подходящего исходного ответа либо расхождение его связи с документом и требует отдельного разбора.
   До завершения переноса для таких документов сохраняется чтение старой строки типов;
   OID извлекаются из сохранённого текста по шаблону соответствующего класса.
5. Повторить применение схемы и перенос; убедиться, что повторный перенос изменяет ноль строк.
   Проверить уникальность пар в витрине, полноту OID/наименований и неизменность курсоров.
6. Обновить существующие карточки и привязки, синхронизировать схему Metabase и перечитать
   значения поля типов: старый кеш содержит прежние подписи. Проверить фильтры с одним
   и несколькими значениями, затем возобновить DAG.

Рабочие сервисы в рамках аудита использовались для чтения и выполнения проверочных
SELECT через API. Новая схема и новые подписи требуют отдельной выкладки; успешное
выполнение SELECT не означает, что опубликованный дашборд уже изменён.

## Результаты проверки реализации

- Полный тестовый набор с подключением к PostgreSQL: 353 теста прошли. Проверены
  правила, сохранение читаемого текста, отдельные элементы ответа, подписи OID/наименования,
  повторный перенос callback и стабильность закрытых периодов при обновлении витрин.
  После уточнения исторических подписей НСИ и транспортных отказов повторно прошли
  все 263 профильных теста SQL, правил и дашбордов. Схема применена дважды; обновлённый
  модуль transform также применён дважды без ошибок.
- Через API рабочего Metabase выполнены 14 запросов нового SQL: семь карточек с одним
  и двумя выбранными типами. Запросы завершились успешно; там, где тип выводится строкой,
  результаты содержат только выбранные значения. Публикации карточек эти запросы не делают.
- На локальном архиве перенесено 101 279 документов. Итоговая проверка новой витрины:
  149 317 строк и столько же уникальных пар `dwh_id` / `error_type`; пропусков OID в
  подписях НСИ не обнаружено. Повторный перенос изменил ноль документов.
  В 8 595 перенесённых документах с сетевым отказом тип соответствует состоянию
  транспорта; ошибки внутри недоставленного callback его не подменяют. Курсоры ELT
  до и после проверки совпадают.
- У 4 554 локальных документов выбранная транзакция связана с другим `dwh_id` и
  `localUid`, хотя `result_logid` и дата ответа находятся в журнале. Все эти документы
  видимы в отчётах. Скрипт намеренно не переписывает их по сообщению другого документа.
  На рабочем DWH найдено 1 562 документа без совпадения по тройке выбранный LOGID,
  дата ответа и `dwh_id`. Это отдельное несоответствие исторических связей, которое
  нужно устранить перед завершением перехода всего архива на новый формат.

Локальные ресурсы: PostgreSQL и Firebird доступны с авторизацией. На порту Metabase
3000 есть TCP-соединение, но HTTP health завершается разрывом соединения; локальный
Metabase как работающий сервис не подтверждён. Локальный Airflow на 8080 недоступен.

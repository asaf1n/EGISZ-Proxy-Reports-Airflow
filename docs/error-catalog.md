# Справочник ошибок регистрации

Каталог типов отказов ЕГИСЗ: перечень типов по категориям, зона ответственности и
повторяемость, условия правил классификации.

Как отказ превращается в тип — [README §«Классификация ошибок»](../README.md#классификация-ошибок).
Точные регулярные выражения правил — `db/02_functions.sql`.

## Типы ошибок

Классификатор сопоставляет `code` и текст `<message>` из ответа ЕГИСЗ с правилами `dim_error_rules`. Несколько типов в одном документе разделяются `·`.

| Контур | Покрытие |
| ------ | -------- |
| РЭМД | Наименования типов — формулировки НСИ «РЭМД. Классификатор кодов сообщений» (OID `1.2.643.5.1.13.13.99.2.305`, версия 3.18) |
| НСИ 305 | Все 127 мнемоник заведены в `dim_nsi_error_code`. Правило приоритета 2 выводится из справочника для 125 из них — вне его остаются `VALIDATION_ERROR` и `RUNTIME_ERROR`, чьи описания диагностики не несут |
| Обобщённые коды | Для `VALIDATION_ERROR` и `RUNTIME_ERROR` причина определяется текстовыми правилами, а код ответа сохраняется в `parent_nsi_error_code` |
| ИЭМК | Платформенные коды (`XDS.CDA.*`, `XDSDictionaryValidationError` и др.) плюс стандартные коды IHE ITI TF-3 регистрационного пути ITI-41/42; внутренние коды (`CRE-NNN`, `PAT-NNN`) приходят в `codeContext` |
| Нет правила | Отказ показывается собственной формулировкой РЭМД, нормализованной `remd_error_type()` |

### Зона ответственности и повторяемость

Каждый тип в `dim_error_type_group` несёт `responsibility` (кто устраняет причину: `клиника` / `МИС` / `интегратор` / `РЭМД` / `смешанная`) и `is_retryable` (устраняется ли повторной отправкой без правки данных). Обе колонки выводятся в `rpt_error_breakdown` и на дашбордах.

Значения по умолчанию наследуются от категории:

| Категория | Зона ответственности | Устраняется повтором |
| --- | --- | --- |
| Данные пациента | клиника | нет |
| Данные медработника | клиника | нет |
| Ошибки структуры и валидации | МИС | нет |

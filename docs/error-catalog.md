# Справочник ошибок

Виды, категории и типы ошибок ЕГИСЗ, зоны ответственности и условия правил. Как элемент ошибки получает тип — [README §«Классификация ошибок»](../README.md#классификация-ошибок). Точные регулярные выражения — `db/02_functions.sql`. Документ собран из справочников `mart_egisz`. Типы — закрытый список: типы правил и по одному типу «Не распознано» на вид.

## Зоны ответственности

Зона ответственности — кто устраняет причину ошибки. Наименования и описания зон хранит справочник `mart_egisz.dim_responsibility_zones`; категории и типы ссылаются на него. Зона пуста, если ошибка явно не классифицирована или правила для неё нет: у категорий «Ошибки регистрации» и «Прочие» и у типов «Не распознано».

| Зона | Описание |
| --- | --- |
| Настройки МИС | Ошибки, вызванные некорректными настройками МИС |
| Реквизиты клиники | Некорректно указанные реквизиты медицинской организации |
| ЕГИСЗ | Ошибки на стороне ЕГИСЗ, недоступность сервисов Минздрава России |
| Интеграция | Собственные ошибки интеграции: организация не привязана к РМИС, РМИС/МИС не зарегистрирована или не активна в РЭМД, неверный идентификатор репозитория ИЭМК, регистрация медицинской организации в ЕГИСЗ, иная информационная система, ошибки схематронов |
| Связь | Сетевые ошибки доставки сообщений |

Признак «устраняется повтором» (`is_retryable`) — устраняется ли ошибка повторной отправкой запроса без правки данных. В руководствах Минздрава такого признака нет; он задан по смыслу ошибки, у защитного лимита РЭМД — по тексту ошибки «просьба повторить через минуту или позже». МИС подаёт запрос повторно и после ошибок, не устраняемых повтором: отказ по сведениям внешних регистров (ГИП, ФРМР, справочники НСИ, сертификаты) устраняется правкой регистра, после чего тот же запрос регистрируется.

## Вид «Ошибка связи»

Шлюз не доставил сообщение (`LOGSTATE = 3`). Категорий нет. Зона ответственности — «Связь», устраняется повтором — да. Правило — код из текста шлюза и уровень: `Socket error` (Windows Sockets) либо `Error while receiving data from service` (ответ HTTP). Правила заведены по текстам, встречающимся на прод-DWH, для кодов с общепринятым определением; определения и источники приведены в таблице. Код без правила получает тип «Не распознано: ошибка связи» с пустой зоной. Ошибки связи в справочную выдачу `serving_egisz.error_types` не входят.

## Вид «Ошибка асинхронного ответа»

Элемент асинхронного ответа РЭМД (`<item>`: `code` + `message`) или ИЭМК (`RegistryError`: `errorCode` + `codeContext`).

| Контур | Покрытие |
| ------ | -------- |
| РЭМД | Коды НСИ «РЭМД. Классификатор кодов сообщений» (OID `1.2.643.5.1.13.13.99.2.305`, версия 3.18): все 127 мнемоник в `mart_egisz.dim_nsi_error_codes`. Правило приоритета 2 выводится из справочника для 152 из них; вне его `VALIDATION_ERROR` и `RUNTIME_ERROR`, причину которых определяют текстовые правила |
| ИЭМК | Платформенные коды (`XDS.CDA.*`, `XDSDictionaryValidationError` и др.) и стандартные коды IHE ITI TF-3 пути ITI-41/42; внутренние коды (`CRE-NNN`, `PAT-NNN`) приходят в `codeContext` |
| Нет правила | Тип «Не распознано: ошибка асинхронного ответа», категория «Прочие»; нормализованный текст — отдельный атрибут `normalized_text` |
